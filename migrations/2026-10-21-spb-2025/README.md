## 원본에서 손본 것 한 가지

**`SO-2502-010` 이 두 거래처에 쓰였습니다.** 2025-02-15 같은 날
PT. SIBA SURYA(SEMARANG, 1라인)와 LARISMA BAN(JAKARTA, 2라인)이 모두 SO 010 입니다.
한 전표에 거래처가 둘일 수는 없어서, 엑셀에서 먼저 나오는 SIBA SURYA 가 010 을
갖고 **LARISMA BAN 은 `SO-2502-028`** (2월 마지막 번호 027 다음)로 넣습니다.
`so_ref` 칸에는 원래 번호 `010` 이 그대로 남아 있어 엑셀과 대조할 수 있습니다.
금액·수량은 바뀌지 않습니다.

**참고 — 비어 있는 번호 두 개.** `SO-2503-024` 와 `SO-2509-013` 은 원본에 행이
없습니다. 취소 전표로 보이며, 만들어 넣지 않았습니다.

## 적용 규칙

8월 적재(`2026-09-15-spb-agustus/30_insert.sql`)와 같습니다.

- `penjualan.id` = `'SO-' || upper(substr(md5(no),1,6))`
- `penjualan.no` = `SO-25MM-NNN` (엑셀 `SO` 열의 월별 일련번호)
- `status` = `lunas` — 미수금·여신한도 계산에서 빠집니다
- `gudang` = SURABAYA→`SBY`, SEMARANG→`SMG`, JAKARTA→`KRW`

8월과 **다른 점 두 가지**:

- **`tgl_kirim` = `tgl` 로 채웁니다.** 원본에 별도 출고일이 없습니다. 오른쪽
  일자 칸도 PO Date 와 같은 날에 수량이 있습니다. 8월 적재분은 이 칸이 비어 있습니다.
- **재고 이동(`stok_mutasi`)을 만들지 않습니다.** 재고 원장은 2026-09-15 에 전량
  초기화했고([2026-09-15-reset-stok-pembelian](../2026-09-15-reset-stok-pembelian/README.md)),
  2026년 1~8월 출고분도 그때 지웠습니다. 2025년 출고만 넣으면 현재 재고가
  2,650 EA 만큼 음수가 됩니다. INSERT 라서 출고 트리거도 돌지 않습니다.

## 실행 순서

Neon **콘솔**(SQL Editor)에서는 `\copy` 가 동작하지 않습니다. 콘솔이면 0번을
`00_staging_konsol.sql`(같은 398행을 INSERT 로 넣는 파일)로 쓰십시오.

```bash
cd migrations/2026-10-21-spb-2025
psql "$DATABASE_URL" -f 00_staging.sql    # 스테이징만. 본 테이블 안 건드림
                                          # (Neon 콘솔이면 00_staging_konsol.sql)
psql "$DATABASE_URL" -f 10_dry_run.sql    # 읽기 전용. 출력 확인
psql "$DATABASE_URL" -f 20_master.sql     # 신규 거래처 20곳 · 품목 1종
psql "$DATABASE_URL" -f 30_insert.sql     # 판매 290전표 / 398라인
psql "$DATABASE_URL" -f 40_verifikasi.sql # 읽기 전용 사후 확인
```

`10_dry_run.sql` 에서 볼 것:

- 1번: 2025년 전표가 이미 있으면 0 이 아닙니다. 이 경우 먼저 알려주십시오.
- 2번: 위 20곳이 나와야 합니다. 목록에 없는 이름이 나오면 멈추십시오.
- 3번: `VG182516AJ101` 한 줄만 나와야 합니다.
- 4번: 세 창고 모두 `ada_di_gudang = t`.
- 5번: 0.

`30_insert.sql` 은 다음 경우 `RAISE EXCEPTION` 으로 멈추고 아무것도 쓰지 않습니다.

- 스테이징이 398행이 아님 (콘솔에서 `\copy` 가 무시된 경우)
- 매칭 안 되는 거래처·품목이 남음 (`20_master.sql` 을 건너뛴 경우)
- 같은 이름의 거래처가 두 행 이상 (전표가 두 번 들어가는 것을 막음)
- 해시 id 가 다른 전표와 겹침

이미 있는 `so_no` 는 건너뛰므로 `20` · `30` 둘 다 다시 돌려도 안전합니다.

## 화면에 생기는 변화

- 요약 화면의 "작년 동기 대비"가 2025년 숫자와 비교됩니다.
- 2025년에만 거래하고 2026년에는 거래가 없는 고객이 "이탈 고객" 목록에 나올 수 있습니다.
- 2025년 전표는 작성자가 없어서 관리자만 수정할 수 있습니다. 당월 문서가 아니므로 수정·삭제는 결재를 거칩니다.

## 검증 방법

로컬 Postgres 14 에 `doc/neon-schema.sql` 을 올리고, 2026년 거래처 56곳과 품목
마스터를 넣은 뒤 다섯 파일을 차례로 돌렸습니다. `00_staging.sql` · `00_staging_konsol.sql`
둘 다 398행이 들어가고, 위 기대값이 모두 나왔으며, `20`·`30` 재실행 시 추가 0건이었습니다.
스테이징 없이 또는 마스터 없이 `30` 을 돌리면 중단되는 것도 확인했습니다.
