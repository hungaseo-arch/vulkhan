# 2026-09-15 — 창고 재고·구매 데이터 초기화

"구매 및 창고 재고 기능은 미활용. 전부 삭제하고, 향후 기능 활용 시
데이터 입력부터 시작." 에 대한 작업입니다.

## 지우는 것

| 테이블 | 현재 | 후 |
|---|---|---|
| `stok_mutasi` (재고 이동 원장) | 전량 | 0 |
| `pembelian` / `pembelian_item` | 0건 (이미 비어 있음) | 0 |

## 지우지 않는 것

`penjualan` / `penjualan_item` — **판매 전표는 그대로**입니다.
1~8월 매출 348전표 / 477라인과 월별 집계는 이 작업 전후가 동일합니다.
판매 화면·대시보드·매출 보고서는 영향받지 않습니다.

## 알고 넘어가야 할 것 두 가지

**1. 재고가 전부 0이 되고, 그 상태에서는 출고가 막힙니다.**

재고는 저장되지 않고 `stok_mutasi` 에서 계산됩니다(`v_stok`). 원장이 비면
모든 창고·품목이 0이 되고, 판매 전표를 `Pengiriman`(출고)으로 넘길 때 걸려
있는 재고 검사에 막혀 "Stok … tidak cukup" 로 거절됩니다.

즉 **재고 기능을 다시 쓰기 시작할 때는 기초재고 입력이 먼저**입니다
(재고 화면 → 기초재고). 그 전까지 판매는 견적·주문 단계까지만 가능합니다.
지금 판매 전표를 출고 상태로 넘기고 계신다면 이 작업은 그 흐름을 멈춥니다.

**2. 판매 1~8월의 출고 기록도 함께 사라집니다.**

원장의 대부분은 판매에서 나온 출고분(`ref` = 전표번호)입니다. 이것만 남기고
나머지를 지우면 재고가 크게 음수로 시작하므로, 부분 삭제는 오히려 더
나쁩니다. 그래서 전량 삭제입니다. 판매 전표 자체에는 품목·수량·단가가
그대로 남아 있으므로 "무엇을 얼마나 팔았는지" 는 잃지 않습니다.

되살리려면 8월분은 [2026-09-15-spb-agustus](../2026-09-15-spb-agustus/README.md)
의 `30_insert.sql` 이 만드는 것과 같은 방식으로 다시 넣어야 합니다.

## 실행

Neon SQL Editor 에서 순서대로:

```
00_cek.sql    -- 읽기 전용. 지워질 내용 확인
10_reset.sql  -- 실제 삭제. 되돌릴 수 없음
```

`00_cek.sql` 의 4번(현재 창고 재고)은 나중에 비교할 일이 있을 수 있으니
결과를 캡처해 두시는 편이 좋습니다.

## 이후 동작

- 전표 수정 기능은 **비워진 원장을 되살리지 않습니다.** `PUT /api/penjualan/:id`
  는 해당 전표에 이동 기록이 *남아 있을 때만* 재작성하며, 없으면 그대로
  둡니다 (api-server.js 의 주석 참고). 옛 전표를 한 건 고쳤다고 해서 지워진
  원장이 한 줄씩 되살아나는 일은 없습니다.
- 앞으로 새로 만드는 전표는 출고 시점에 트리거가 원장을 정상적으로 씁니다.
